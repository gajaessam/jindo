# 우리 반 캐릭터 진도 위젯

Windows 바탕화면 아래쪽, 작업표시줄 바로 위에 반별 캐릭터가 투명 배경으로 보이는 위젯입니다. 작업표시줄을 경주 트랙처럼 사용하며 캐릭터는 해당 반의 전체 활동 완료율에 맞춰 결승 깃발 쪽으로 이동합니다. 활동을 체크하면 위치와 이름표의 퍼센트가 갱신됩니다. 캐릭터를 클릭하면 해당 반의 진도 말풍선이 열립니다. 마우스 오른쪽 클릭 메뉴의 「반 개수·캐릭터 설정」에서 반별 이미지를 정하고, 반 이름 바꾸기, 반 추가, 전체 종료를 할 수 있습니다.

처음 실행하면 캐릭터 그림 없이 은은한 `＋` 이미지 자리표시자가 표시됩니다. 오른쪽 클릭 메뉴의 「반 개수·캐릭터 설정」에서 수업하는 반을 1~20개로 맞추고 반별 이름과 이미지를 지정할 수 있습니다. PNG, JPG, WEBP, BMP, GIF 이미지를 선택할 수 있고 투명 배경 PNG를 권장합니다. 첫 프레임만 사용하며 20MB 이하, 2,400만 픽셀 이하 이미지를 지원합니다. 선택한 이미지는 `%APPDATA%\UsagiJindo\characters`에 복사되어 해당 PC에서만 사용됩니다. 이미지를 비우면 해당 반은 자리표시자로 돌아갑니다. 반을 줄이면 마지막에 있는 반들의 진도와 메모가 삭제되므로 확인창이 표시됩니다. 각 반의 진도창에는 그 반에만 저장되는 메모가 있으며, 입력 즉시 저장됩니다.

「반 개수·캐릭터 설정」에서 모든 캐릭터의 대기 동작을 「살짝 둥둥」 또는 「멈춤」으로 한 번에 설정할 수 있습니다. 진도에 따라 트랙에서 이동하는 동작은 두 설정 모두에서 유지됩니다.

차시와 활동은 공통 계획으로 관리합니다. 어느 반에서 차시나 활동을 추가해도 모든 반에 같은 계획이 추가되고, 완료 체크는 반마다 따로 저장됩니다. 기본 반은 5~10반이며, 첫 차시에 공기환경·소리환경·빛환경·포스터 그리기가 들어 있습니다. 체크 상태와 계획은 `%APPDATA%\UsagiJindo\progress.json`에 저장하고, 저장할 때 직전 정상 파일을 `progress.json.bak`으로 보관합니다. 저장 도중 문제가 생기면 기존 파일을 교체하지 않습니다. 저장 파일을 읽지 못하면 자동 백업을 복구하고, 손상 파일도 `progress.recovery-날짜-시간.json`으로 보존합니다. 진도와 캐릭터 이미지는 PC에 저장되고 외부로 전송되지 않습니다. 이미지 파일을 추가하는 사람은 해당 이미지의 이용 권리를 확인해야 합니다.

## 업데이트 기능

배포된 앱은 시작할 때 공개 GitHub 저장소의 최신 안정 릴리스를 확인합니다. 새 버전이 있으면 변경 내용을 보여주고, 사용자가 동의한 경우에만 내려받습니다. 캐릭터 이미지와 진도 파일은 그대로 두고 앱 파일만 교체합니다. 업데이트 파일은 GitHub 릴리스의 SHA-256 값으로 확인한 뒤 설치하며, 이전 앱 폴더는 같은 위치에 백업으로 남습니다. 인터넷 연결이 필요합니다. 우클릭 메뉴의 「업데이트 확인」으로 직접 확인할 수도 있습니다. Python으로 `app.py`를 실행하는 개발 모드에서는 업데이트 설치 메뉴가 동작하지 않습니다.

이 앱은 `gajaessam/jindo`의 공개 릴리스를 확인합니다. GitHub Releases API는 공개 저장소에서 인증 없이 사용합니다. GitHub에 릴리스 파일을 올리면 앱은 업데이트 확인 요청을 보내며, 업데이트 다운로드는 앱에서 설치를 선택했을 때 시작됩니다.

### 릴리스 ZIP 만들기

Windows에서 Python 3와 Tcl/Tk를 설치한 뒤 프로젝트 폴더에서 아래를 실행합니다.

```powershell
python -m pip install -r requirements-build.txt
.\build_release.ps1
```

빌드 결과는 `release\UsagiJindo-v0.2.0-Windows-x64.zip`처럼 `release` 폴더에 생깁니다. ZIP 안에는 `우리 반 진도` 폴더가 포함되고 그 안에 앱 실행 파일, PyInstaller 파일, `UsagiJindoUpdater.exe`가 들어갑니다. ZIP을 원하는 위치에 풀되 앱 폴더 이름은 `우리 반 진도`로 유지해 주세요. 앱은 이 폴더만 교체하므로 바탕 화면이나 문서 폴더에 ZIP 내용을 직접 풀지 마세요. 이 ZIP을 GitHub 저장소의 Releases에 해당 버전 태그로 첨부합니다. 첫 업데이트 사용자가 받을 기준 릴리스는 `v0.2.0`입니다. 다음 릴리스를 만들 때 `update_config.py`의 `APP_VERSION`을 예를 들어 `0.2.1`로 올리고 다시 빌드한 다음, GitHub Release 태그를 `v0.2.1`로 만들어 해당 ZIP을 첨부합니다. 파일 이름은 코드가 찾는 이름과 정확히 일치해야 합니다.

빌드 스크립트는 Windows용 앱 폴더와 별도 업데이트 도우미를 만든 뒤 앱 폴더의 내용물을 ZIP으로 묶습니다. 릴리스를 게시하는 작업은 GitHub에서 직접 해야 합니다. 앱 실행 파일에는 코드 서명이 포함되지 않으므로 Windows가 최초 실행 시 게시자 확인 안내를 표시할 수 있습니다.

## 실행

Python 3와 Pillow가 필요합니다. `시작하기.bat`을 더블클릭해 실행하세요. 실행 중 모든 캐릭터를 종료하려면 캐릭터를 오른쪽 클릭하고 「전체 종료」를 선택합니다. `Ctrl+Shift+Q`도 종료 단축키입니다.

위젯은 프로그램에 동봉된 캐릭터 그림을 불러오지 않습니다. 배포할 때는 원본 캐릭터 이미지 파일을 포함하지 말고 앱 코드와 실행 파일만 배포하세요. 반 설정에서 각자 사용할 이미지를 선택하면 됩니다. 위젯과 작업표시줄 배치는 현재 기본(주) 모니터 기준이며, DPI 배율과 화면 크기 변경을 감지해 위치를 다시 맞춥니다. 보조 모니터에는 위젯을 표시하지 않습니다.
